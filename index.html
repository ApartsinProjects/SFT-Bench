Semantic Feature Transfer with Knowledge-Graph Embeddings

Alex Partsin
Working draft, 2026
SFT-Bench: a cross-domain benchmark for semantic feature transfer
Code & repository Research plan Phase-1 spec Dataset notes

Abstract. Predictive models usually treat input features as anonymous dimensions. A model may learn extensively from a feature such as reactor pressure or supply-air temperature, yet it has no explicit mechanism for reusing that knowledge when a new but semantically related feature appears, such as separator pressure or return-air temperature. We study whether representing each numerical feature together with a semantic embedding derived from a domain knowledge graph lets a model reuse predictive behaviour across semantically related features, and therefore require fewer labeled examples when new sensors, variables, or measurement types are introduced. We formalise this as semantic feature transfer, define a label-efficiency measure for it, and introduce SFT-Bench, a cross-domain benchmark spanning building systems, industrial control, and process monitoring, each paired with an independent ontology. We specify a construct-matched evaluation protocol in which the feature encoder is held fixed and only the semantic embedding varies, with pre-registered invariants that separate a genuine semantic effect from a merely architectural one. Empirical validation across the benchmark is in progress; this draft presents the formulation, the benchmark, and the protocol.

1. Introduction

Models know the numerical values of their features but usually do not know what those features mean.

A conventional model ties the identity of each feature to a fixed input position and learns a mapping \( f(x_1,\ldots,x_m)\rightarrow y \). When a new but related feature is introduced, that model sees only a new anonymous column and must learn its behaviour from target data alone, even when it has already learned a great deal from a feature that measures the same physical quantity on a related component. We call the resulting problem the new-feature cold-start: a feature whose meaning is known from a domain ontology but whose predictive behaviour has not yet been observed.

External domain knowledge offers a way in. A knowledge graph that states a sensor measures pressure, is located at a separator, and is part of a process system places that sensor near others that share those properties. If a model is organised so that its per-feature computation is keyed on such semantics rather than on column position, then behaviour learned for one feature can apply to a semantically neighbouring feature that the model has never seen during training.

2. Problem definition

We represent a sample not as a bare vector but as a set of semantically described measurements, \[ X = \{(x_j, e_j)\}_{j=1}^{m}, \] where \(x_j\) is the observed value or short temporal window for feature \(j\) and \(e_j\) is a semantic embedding derived from a domain ontology. A shared feature encoder maps every pair to a representation \[ z_j = F_\theta(x_j, e_j), \] the encoded features are combined by a permutation-invariant aggregator \( z = A(z_1,\ldots,z_m) \), and a head predicts \( \hat y = G(z) \). Because the same \(F_\theta\) processes every feature, the model can learn rules associated with semantic concepts rather than with fixed columns. For a previously unseen feature \(j^{*}\), an embedding \(e_{j^{*}}\) is generated from its ontology neighbourhood, so the encoder produces a representation for it without ever having seen its identity during training.

We measure the contribution in terms of label efficiency rather than absolute accuracy. Let \(K_M(q)\) be the number of labeled target examples model \(M\) needs to reach performance \(q\). Semantic transfer efficiency is \[ \mathrm{STE}(q) = \frac{K_{\text{baseline}}(q)}{K_{\text{semantic}}(q)}, \] so an \(\mathrm{STE}(0.90)\) of five means the semantic model reaches AUROC 0.90 with one fifth of the target labels the baseline requires.

3. Method

The semantic embedding \(e_j\) is the object under study, so the method is defined as a family of embedding sources evaluated inside one fixed architecture. We consider a random embedding (a fixed vector per feature), a learned per-feature identity embedding, a text embedding of the feature name, unit, and component description, a metadata embedding of measurement type, component type, and unit without graph topology, and a knowledge-graph embedding produced by an inductive encoder over the feature's ontology neighbourhood. The graph encoder is inductive by design, so an unseen feature node receives an embedding from its relations without retraining the graph.

4. SFT-Bench

SFT-Bench evaluates the same method across independent domains rather than across splits of a single dataset. Each domain contributes labeled data, an independent ontology, and common transfer protocols under one unified representation, so datasets with different feature counts share the same architecture.

The reference domain for Phase 1 is the LBNL Fault Detection and Diagnostics single-duct air-handling-unit dataset, distributed under CC-BY with a Brick model for the sensor points. The dataset is generated by building simulation; Phase-1 claims are scoped to that setting, and the industrial-control domain provides the real-testbed evidence. The single-duct unit contributes thirty points across the air handler, its fans, dampers, cooling coil, and five zones, with fault scenarios that localise to specific components. This gives ready-made transfer axes keyed on Brick semantics: a temperature-sensor fault on one location paired with the same fault on another, and an actuator-stuck fault on one component paired with the same fault on a different component.

5. Evaluation protocol

The protocol is construct-matched: across every condition the temporal encoder, the shared feature encoder, the aggregator, the head, the splits, and the seeds are identical, and only the embedding \(e_j\) changes. Embeddings are padded to a common dimension so that no condition receives more parameters than another, and every comparison is computed in a single pass and saved as one artifact. The conditions are summarised below.

ConditionEmbeddingWhat it establishes
Value onlynonefloor without semantics
Randomfixed random vectorcontrols for extra dimensions
Learned identitytrainable per-featurein-distribution reference; cannot embed an unseen feature
Textsentence embedding of name, unit, componentthe strong semantic competitor
Metadatatype, component type, unitisolates the value of graph topology
Knowledge graphinductive ontology encoderthe proposed representation
Shuffled graphpermuted feature-to-node mapseparates a semantic effect from an architectural one

Two comparisons decide the central question. Knowledge-graph against text tests whether explicit graph structure adds value beyond what a modern text encoder already captures from the same metadata. Correct-graph against shuffled-graph, on an identical architecture, tests whether any benefit is semantic rather than a by-product of the shared encoder. The protocol carries pre-registered invariants whose expected outcomes are stated before each run: a degenerate value-only model matches a plain fixed-column model on full data; performance is non-decreasing in the number of target labels; the correct graph is at least as good as the shuffled graph, which is at least as good as the random embedding; and the learned-identity condition cannot succeed at zero-shot on a held-out feature. A violated invariant is treated as a defect to locate rather than a result to report.

Each domain runs the same experiments: standard full-data prediction as a check that semantic representation does not degrade ordinary performance; few-shot feature transfer, measuring performance as a function of the number of target labels \(K\); zero-shot feature cold-start, where a feature is withheld entirely during training and only its values and ontology metadata are available at test time; component cold-start, where an entire component, stage, or instance is held out; and cross-dataset transfer within a domain.

6. Semantic-distance analysis

Beyond aggregate accuracy, the benchmark tests whether semantic distance predicts transferability. For each feasible source-target feature pair we compute a semantic similarity \(S_{ij}=\operatorname{sim}(e_i,e_j)\) and an empirical transfer gain \[ T_{ij} = \mathrm{Performance}_{\,i\rightarrow j} - \mathrm{Performance}_{\,\text{scratch}(j)}, \] and examine \(\mathrm{corr}(S_{ij}, T_{ij})\). A positive relationship would support the deeper claim that semantic similarity predicts statistical transferability, and would also indicate when graph structure, causal direction, or operating regime must enter the embedding for similarity to track transfer.

7. Status

The reference implementation and the single-pass evaluation harness are in place for the Phase-1 building-systems domain: dataset conversion to the unified representation, the Brick graph parser, the seven embedding conditions, the shared-encoder model, the transfer splits, and the pre-registered sanity gate. Full cross-domain transfer results are in progress and will be reported with confidence intervals over seeds and held-out features as learning curves and semantic-distance scatter plots.

8. Related work

The approach connects transfer learning and tabular transfer, schema and entity matching, knowledge-graph embeddings and inductive graph learning, set and feature-token architectures, metadata-aware and ontology-informed models, and the application literatures of industrial fault diagnosis and cross-dataset clinical prediction. The distinguishing element here is the combination of an inductive semantic embedding with a shared, position-free feature encoder evaluated for label efficiency across independent ontologies.

9. Conclusion

External semantic knowledge can act as a prior over feature identity, letting predictive models reuse learned behaviour when new but semantically related variables appear. SFT-Bench and its construct-matched protocol are designed to measure that effect cleanly, to attribute it to graph structure where structure matters, and to express it as a reduction in the target labels required to reach a fixed level of performance.
